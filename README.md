# Secure REST API

## 1. Описание проекта

Учебный проект по разработке защищённого REST API на Python с использованием Flask, SQLite и JWT. Проект демонстрирует базовые меры защиты веб-приложения и интеграцию автоматизированных проверок безопасности в CI/CD.

## 2. Используемые технологии

- Python 3.12
- Flask
- Flask-SQLAlchemy
- SQLite
- Flask-JWT-Extended
- Argon2
- Pytest
- Bandit (SAST)
- pip-audit (SCA)
- GitHub Actions

## 3. Установка и запуск

Создать виртуальное окружение и установить зависимости:

```bash
python -m venv .venv
python -m pip install -r requirements.txt
```

Создать файл `.env` с переменной `JWT_SECRET_KEY`, содержащей случайный секретный ключ.

Инициализировать базу данных:

```bash
flask --app app init-db
```

Создать пользователя:

```bash
flask --app app create-user student
```

Запустить приложение:

```bash
flask --app app run
```

## 4. API

### GET /health

Проверяет доступность сервиса. Авторизация не требуется.

### POST /auth/login

Принимает JSON:

```json
{
  "username": "student",
  "password": "your-password"
}
```

При успешной авторизации возвращает JWT в поле `access_token`.

### GET /api/data

Возвращает список записей. Требует JWT в заголовке:

`Authorization: Bearer <token>`

### POST /api/data

Создаёт запись. Требует JWT и JSON:

```json
{
  "title": "Название",
  "content": "Содержимое"
}
```

Успешное создание возвращает HTTP 201.

## 5. Реализованные меры безопасности

### SQL Injection

Для работы с базой используется SQLAlchemy ORM и параметризованное построение запросов. Пользовательский ввод не конкатенируется с SQL-командами.

### XSS

API экранирует HTML-значимые символы в пользовательских строках перед возвратом данных. Клиентская сторона также должна безопасно отображать текст, избегая небезопасной вставки HTML.

### Аутентификация

Пароли хранятся в виде хэшей Argon2. При входе пароль проверяется по сохранённому хэшу. После успешной проверки сервер выдаёт JWT с ограниченным временем действия.

Защищённые маршруты используют `@jwt_required()`. Запрос без действительного токена отклоняется.

### Управление секретами

Секретный ключ JWT загружается из переменной окружения. Файл `.env` исключён из Git. Для CI применяется отдельное тестовое значение.

### Проверка входных данных

Проверяются типы, наличие и максимальная длина полей. Некорректные запросы отклоняются.

## 6. Автоматизация безопасности

GitHub Actions запускается при `push` в `main` и при Pull Request.

- Pytest — функциональные тесты API.
- Bandit — статический анализ Python-кода (SAST).
- pip-audit — проверка сторонних зависимостей (SCA).
